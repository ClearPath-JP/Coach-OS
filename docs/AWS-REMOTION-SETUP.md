# Remotion Lambda — AWS Setup (Gate 2)

Goal: provision the AWS pieces so Kindo's Promote video editor can render in the cloud.
Region: **us-east-1**. Remotion version: **4.0.468**.

Policy JSON files (generated by `npx remotion lambda policies …`) live next to this doc:
- `../remotion/aws/role-policy.json`  → the Lambda **execution role** policy
- `../remotion/aws/user-policy.json`  → the **IAM user** (deployer) policy

---

## Step 0 — Create the AWS account (YOU — can't be automated)
Needs a credit card + phone verification. Go to https://aws.amazon.com → "Create an AWS Account".
Use the **root** login only for the IAM steps below, then stop using it.
Cost expectation: Remotion Lambda renders cost ~fractions of a cent each; this stays in/near free tier for low volume.

## Step 1 — Create the execution role policy
IAM → Policies → Create policy → JSON tab → paste `remotion/aws/role-policy.json`.
Name it exactly: **remotion-lambda-policy**

## Step 2 — Create the execution role
IAM → Roles → Create role → Trusted entity: **AWS service** → Use case: **Lambda** → Next.
Attach the policy **remotion-lambda-policy** (from Step 1).
Name it exactly: **remotion-lambda-role**   ← must be this exact name; Remotion looks it up by name.

## Step 3 — Create the deployer IAM user
IAM → Users → Create user. Name: **remotion-deployer** (any name is fine).
Do NOT give it console access. Permissions → "Attach policies directly" →
   Create inline policy → JSON → paste `remotion/aws/user-policy.json` → name it **remotion-user-policy**.

## Step 4 — Generate access keys for that user
Open the user → Security credentials → "Create access key" → use case "Application running outside AWS"
→ create. Copy BOTH values now (the secret is shown only once):
   - Access key ID
   - Secret access key

## Step 5 — Put the keys in .env.local  (YOU paste — Claude never edits .env)
Add these four lines to `C:\Dev\ClearPath\COACH-OS\.env.local`:
```
REMOTION_AWS_ACCESS_KEY_ID=<access key id>
REMOTION_AWS_SECRET_ACCESS_KEY=<secret access key>
REMOTION_APP_REGION=us-east-1
```
(The remaining two — `REMOTION_APP_FUNCTION_NAME` and `REMOTION_APP_SERVE_URL` — are produced by
Step 6 and I'll tell you the exact values to add.)

## Step 6 — Claude runs these (CLI, from the repo)
```
npx remotion lambda policies validate      # confirms the IAM setup is correct
npx remotion lambda functions deploy       # creates the render function → FUNCTION_NAME
npx remotion lambda sites create remotion/index.ts --site-name=kindo-captioned  # → SERVE_URL
```
Then you add to `.env.local`:
```
REMOTION_APP_FUNCTION_NAME=<printed by functions deploy>
REMOTION_APP_SERVE_URL=<printed by sites create>
```

## Step 7 — Live cloud render test (Claude)
`node --env-file=.env.local screenshots/render-poll.mjs` (or via the in-app render route) against the
fixture video to confirm an end-to-end cloud render returns a downloadable mp4.
